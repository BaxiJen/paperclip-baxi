# Plugin externo dsh_local — 2026-10-06

Implementar `@baxijen/paperclip-adapter-dsh` sem registro built-in, migração,
telemetria ou instalação global. Contrato verificado no fonte dsh 0.2.1-alpha.1.

1. Reutilizar o empacotamento do Kiro e o contrato externo de parser de transcript.
2. Configurar provedor/modelo por schema, com campos condicionais para API própria,
   sugestões por provedor e segredo via SecretPicker. Ligar o schema ao fluxo de
   criação somente para dsh_local, pois esse fluxo ainda não renderiza schemas externos.
3. Gerar overlay por execução, contendo apenas referências de ambiente; isolar
   DSH_HOME por empresa/agente; prompt por stdin; sessão vinculada ao escopo.
4. Publicar NDJSON redigido ao vivo, exigir final + turno concluído + exit 0,
   limitar saída e encerrar grupo de processos em timeout/cancelamento.
5. Diagnosticar binário, Node e autenticação via GET de modelos, sem inferência.
6. Testar com CLI falso, mocks HTTP, schema/credenciais/UI, bundle independente,
   typecheck e gates locais. Documentar restrições do sandbox e prova no commit base.

Entrega permanece no working tree, sem commit/push/deploy. A validação real da VPS
(instalação dsh, systemd PATH, provedores, retomada e filhos) fica explicitamente separada.

## Implementação e decisões

- Pacote externo com `createServerAdapter`, `getConfigSchema`, codec de sessão,
  suporte a JWT local e export browser `./ui-parser`. Bundle esbuild inclui
  adapter-utils; não depende de workspace/node_modules na VPS.
- A conexão usa schema existente: provedor, campos condicionais para API própria,
  combobox com sugestões/texto livre e esforço opcional. O SecretPicker vincula
  `secret_ref`/`user_secret_ref`; a chave digitada precisa ser salva explicitamente
  no serviço de segredos antes do teste. Configuração fica em adapterConfig,
  valores de chave ficam no serviço de segredos e são resolvidos pelo host.
- Testar ambiente verifica Node, versão do CLI e GET de modelos sem inferência.
  Falha de listagem permite ID manual com aviso; 401/403 ou chave ausente falham
  com `adapter_auth_missing`. Sugestões do combobox são fixas por provedor; a lista
  descoberta aparece no resultado do teste, não alimenta um novo endpoint/UI.
- Dois patches de UI adicionais foram indispensáveis: NewAgentSetup não renderizava
  schemas externos na criação; AgentConfigForm ocultava o modelo do schema para
  motores locais. As exceções são restritas a dsh_local e reutilizam componentes.
  O único componente novo de produção é o ícone.
- DSH_HOME fica no instance root, em adapter-homes/dsh/company/agent. Overlay
  exclusivo de cada run (0600) usa nomes de env, nunca valores, e é removido no fim.
  Prompt vai por stdin; TMPDIR usa paperclipScratch.dir; ambiente enriquecido do
  host é filtrado sem confundi-lo com env configurado pelo operador.
- Saída incremental redigida, limite combinado de 4 MiB, final completo, usage
  per_run, retry único de sessão recusada antes de trabalho e encerramento de
  grupo de processos. Compatibilidade deliberadamente restrita a dsh 0.2.1-alpha.1.
- SVG fornecido copiado sem alteração: SHA256
  `deba5f98a5c1796e20fcac3149bcd7eb8a32f0bdd04d048819400b1f28bd1439`.

## Pendências para VPS / ambiente sem sandbox

1. Reexecutar suite completa, smoke do bundle e gates raiz; os testes reais de
   stdin, retomada, cancelamento e filhos ainda precisam passar.
2. Instalar o pacote externo via POST /api/adapters/install com isLocalPath e
   validar carregamento do parser pelo host. O CLI continua dependência externa.
3. Confirmar PATH/Node do usuário paperclip no systemd, diretórios persistentes,
   permissões e scratch. Exercitar um turno real e retomada no mesmo cwd/preset.
4. Testar chaves reais e catálogos de cada conta/gateway. GET de modelos não
   comprova acesso à inferência, protocolo ou reasoningEffort de um modelo.
5. Revisar retenção das conversas/ferramentas pelo próprio dsh e permissões de
   execução na VPS. O adapter não altera a política de ferramentas do CLI.
